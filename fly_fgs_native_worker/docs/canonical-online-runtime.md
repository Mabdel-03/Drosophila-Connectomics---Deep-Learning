# Canonical online visual-to-flight runtime

The canonical online path uses the captured `/fly-fgs` circuit as the only
motor-eligible visual circuit. Its source application mechanics (`SCALE_M`,
`muscleAct`, `ampL`, `ampR`, and algebraic yaw) are excluded.

```text
body state + figure world state
        │  every 5 ms
        ▼
canonical fly-FGS circuit (1,684 cells; only four NOD1 voltages motor eligible)
        │  measurement and availability receipts
        ▼
streaming NOD1 → DNp26 → iv2/i1/iv1/b3 MN bridge (0.5 ms)
        │  seeded phase-gated events; NMJ availability ≥ 0.5 ms
        ▼
power/tension carrier + named steering muscles + virtual hinge (0.1 ms)
        │  left-boundary zero-order-hold command
        ▼
explicit raw-app-lane → physical-wing hypothesis
        │
        ▼
FlyBody/MuJoCo adapter (0.1 ms) → body state → next visual sample
```

The dedicated native worker pins CPython 3.12.11, Node 22.22.1, FlyGym 2.1.0,
and MuJoCo 3.9.0. The original design assumption of Python 3.11 is not viable
for the official FlyGym 2.1.0 distribution: its package metadata requires
Python 3.12 or newer and its normal import path uses `typing.override`. Keeping
the supported distribution is preferable to silently maintaining a numerical
fork. The dependency-light simulator and evidence tools remain usable on
Python 3.9 and newer.

## Causal contract

- Circuit observations occur exactly at `0, 5, 10, … ms`. Sample zero is the
  captured static pre-roll and is accepted only after a retinal-angle gauge
  check.
- A bridge interval is half-open and exactly 0.5 ms. It starts by releasing
  only NMJ events generated by earlier intervals.
- Mechanics advances through five exact 0.1 ms intervals. The six phase
  endpoints are returned to the bridge so preferred-phase crossing times are
  computed piecewise rather than from a fabricated linear 0.5 ms phase ramp.
- The physics command for `[t, t + 0.1 ms)` is the mechanics state available at
  `t`. An NMJ event inside that interval changes the following command and can
  never act retroactively.
- Circuit, bridge, mechanics, physics, rendering, and logging clocks are
  separate. Discrete events are never linearly interpolated.

Any exception after a component has mutated poisons the composite runner. The
caller must restore the previous complete composite checkpoint into fresh
objects; partial continuation is forbidden.

## Muscle interventions

`StreamingMuscleIntervention` is a frozen, SHA-bound force-stage contract for
iv2, i1, iv1, or b3. Bounds lie on the exact 0.1 ms grid and are half-open.

- `SILENCE` gates effective activation and force to zero immediately and
  suppresses NMJ excitation that becomes available while active. Natural
  hidden state continues to decay and is logged separately.
- `SCALE` changes effective output only. It does not rewrite the natural hidden
  state.

Applied, suppressed, active, and pending IDs are checkpointed. The bridge's
older `MUSCLE` intervention target affects command-rate generation only; it is
not a substitute for this force-stage intervention.

The complete registered native comparison contract is
`data/benchmarks/scenarios/canonical-online-native-pair.v1.json`; it binds the
intervention fixture
`data/benchmarks/scenarios/canonical-online-raw-l-iv2-silence.v1.json`. The
perturbation silences raw-app-L iv2 over the exact half-open interval
`[60, 100) ms`. It runs against a baseline with the same seed, moving figure,
effector hypothesis, compiled worker, and source receipts. The pair must be
identical before intervention onset. After an effect can reach physics and then
the next 5 ms visual sample, closed-loop circuit traces are allowed to diverge;
treating the entire upstream trace as an immutable open-loop control would be
incorrect.

## Laterality boundary

The source application labels are `raw_app_L` and `raw_app_R`. They are not
anatomical sides. FAFB soma-x laterality does not resolve this application
label. Every run must select one of two explicit physical actuator hypotheses:

- raw app L → physical left wing;
- raw app L → physical right wing.

The mapping permutes every bilateral wing field, including both three-axis
torque triplets, immediately before the physics adapter. Its hypothesis,
UNKNOWN anatomy, provenance, and policy are bound into configuration, results,
and checkpoints. Signed yaw and roll claims are prohibited until independent
evidence resolves this boundary. Both hypotheses must be reported for any
direction-sensitive exploratory result.

## Immutable publication

`write_canonical_closed_loop_artifact` writes a new directory atomically. It
contains:

- chunked, unit-annotated arrays on circuit, bridge, and physics clocks;
- exact NOD1 voltages, inferred DN/MN rates, six-point phase paths, natural and
  effective muscle state, raw and physical actuation, body state, measured
  articulated telemetry, and aerodynamic wrench where available;
- discrete motor-event and circuit-observation tables;
- the complete resume checkpoint and per-component checkpoint receipts;
- runtime/backend receipts, limitations, effector mapping, and manifest hash.

Reset-boundary wrench and articulated telemetry are captured before the first
transition. The publisher never copies a future transition into `t=0`. The
natural muscle trace starts at its first observed right endpoint because the
current mechanics record does not expose a distinct natural left-boundary
snapshot.

The browser replay is a derived projection with its own digest stored in the
artifact. Artifact-reference fields are excluded from that projection digest,
allowing the immutable manifest hash to be attached after atomic commit without
creating a circular hash.

Generate a 100 ms moving-figure baseline in the pinned worker, including the
registered 1,684-cell state for the display-only circuit workspace:

```bash
python -m fly_sensor2behavior.cli simulate-canonical-online \
  --output /tmp/canonical-online-baseline \
  --web-replay-output /tmp/canonical-online-baseline.web.json \
  --scenario-id canonical-online-baseline \
  --label "Canonical online baseline" \
  --duration-s 0.1 --seed 73 \
  --figure-velocity-rad-s 0.5235987755982988 \
  --effector-hypothesis raw_l_to_physical_left
```

Generate the registered force-stage perturbation with every other input held
fixed:

```bash
python -m fly_sensor2behavior.cli simulate-canonical-online \
  --output /tmp/canonical-online-raw-l-iv2-silence \
  --web-replay-output /tmp/canonical-online-raw-l-iv2-silence.web.json \
  --scenario-id canonical-online-raw-l-iv2-silence \
  --label "Raw-app-L iv2 silence" \
  --duration-s 0.1 --seed 73 \
  --figure-velocity-rad-s 0.5235987755982988 \
  --effector-hypothesis raw_l_to_physical_left \
  --muscle-interventions \
    data/benchmarks/scenarios/canonical-online-raw-l-iv2-silence.v1.json
```

Publish only after both commands complete and their summaries are reviewed:

```bash
python scripts/publish_canonical_web_run.py \
  --artifact-dir /tmp/canonical-online-baseline \
  --replay /tmp/canonical-online-baseline.web.json \
  --episode-id canonical-online-baseline \
  --condition "moving figure; baseline" \
  --description "Live fly-FGS circuit through the causal actuator and native FlyBody." \
  --color '#2dd4bf' \
  --position 0
```

The publisher verifies all circularity-safe receipts and makes the public index
visible last. It cannot promote an exploratory result; the regenerated
validation report and `scripts/audit_web_release.py` remain independent release
gates.

## What the current runtime establishes

Hard self-supervised gates establish software behavior: exact clocks,
no-future-read semantics, phase crossing, event delivery, intervention
semantics, effector permutation, finite output, source receipts, composite
checkpoint integrity, and fresh-object/fresh-process continuation.

They do **not** establish:

- calibrated compound-eye irradiance, photoreceptor/lamina/T5 processing, or
  translation/parallax vision;
- a physiological DNp26 transfer function or spike timing;
- calibrated asynchronous power, tension, steering muscle, thorax, hinge, or
  tendon parameters;
- measured wing phase feedback into the VNC model;
- resolved anatomical laterality or signed steering direction;
- FlyBody steady-flight equivalence, timestep convergence against the official
  released ordinary-flight archive, or held-out biological validity.

Those claims remain `blocked` or `exploratory` in the benchmark registry until
their declared evidence and held-out protocols are available. A passing
software gate must never promote them implicitly.
